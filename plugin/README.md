# 光鸭 STRM 同步 · DIAN-115 插件 0.6.3

单账号，页面只有账号登录和设置；任务进度和结果统一在系统任务队列查看。要求宿主插件 API 3.8。

## 安装

导入 `guangya-strm-0.6.3.dian115p` 升级，保留原 ID、账号凭证、规则和同步状态。不需要卸载旧版。旧任务运行期间宿主可能拒绝升级，请先完成任务。

## 云盘名称和路径

编辑规则时从宿主 `/api/cd2/clouds` 自动读取已挂载的光鸭名称，只读显示，例如 `/光鸭云盘`。仅有一个光鸭挂载时自动选中；多个挂载时仅沿用可明确匹配的既有挂载，不凭空选择账号。无挂载、接口失败或有多个无法匹配的挂载会报明原因。

源路径由光鸭账号浏览选择，例如 `/已整理`；下面按内置 115 样式显示 `CD2路径：/光鸭云盘/已整理`。CD2 备用入口保留在网盘浏览失败时的目录选择器中，高级设置不再出现备用或网盘根目录字段。

CD2 模式生成的 STRM 内容仍是完整路径 `/CloudNAS/CloudDrive/光鸭云盘/已整理/…/视频.mkv`。挂载前缀依据本 NAS 用户提供的原生 115 STRM 适配，同步时确认虚拟目录存在且完整路径被宿主识别为 CD2。不会通过修改显示文字掩盖路径错误。旧规则运行时也会读取实际挂载名称。

链接模式沿用当前 DIAN115 播放回调地址和已保存令牌，源目录仍通过光鸭账号扫描，不依赖 CD2 播放。整理触发需要可匹配的 CD2 云盘目标路径；没有 CD2 挂载时仍可手动或定时使用链接模式。

## 同步模式

- 规则启用后，可勾选“整理后增量”（新旧规则默认开启），独立于定时同步开关；界面按内置115命名为“实时监控”，其实际实现仍为每分钟检测整理成功历史。
- 后台每分钟只读检查 DIAN115 `/api/organize/history` 的成功记录，根据实际目标完整路径或 CD2 虚拟路径匹配光鸭规则的源目录，并尊重排除目录。115 和无关本地整理不会触发光鸭扫描。
- 通过公开整理历史接口轮询实现，未假设未经核实的事件名称；不是光鸭实时事件监听。首次后台检查建立基线，不重放安装前的旧成功记录。首次启用后发生的新整理记录才进入检测范围。
- 整理成功后额外等待约一分钟再执行，连续完成按规则合并，自动提交之间至少间隔五分钟。现有同步任务正在等待或执行时不重叠提交，保留待处理请求；增量失败后仍保留版本，下次检查重试。
- 勾选定时同步后，增量按每1/2/6/12小时或每天执行，全量可选不启用、每12小时或每天北京时间凌晨3点。两个同步模式均不选时为手动模式。旧增量cron沿用，修改增量频率后切换为预设。
- 定时全量与整理增量同时待处理时，合并为一次全量；期间到来的新整理结果在下一批次同步。
- 增量仍需扫描选定目录，只写入变化或本地缺失的 STRM 和元数据。没有自动删除，也没有新增日志面板。

宿主成功历史可能在元数据完全写完前出现，一分钟延迟不能保证所有外部插件已经完成写入；之后的整理触发或定时全量会补齐。历史记录读取上限为每次 50 页、每页100条；超过上限会停止检测并通过系统任务记录报告，避免静默跳过。状态检查会保留最近24小时重叠窗口和最多10000条去重指纹。仅识别包含可确认云盘根目录的目标路径；缺少云盘身份的相对目标路径不会猜测归属。

## 其他功能

源文件 `视频.mkv` 输出为 `视频.mkv.strm`，避免相同主文件名、不同后缀互相覆盖。元数据同步仅不启用或云端覆盖，单文件上限64MiB。旧版保留本地模式继续兼容，编辑后默认为不启用。

孤立文件仅支持先预览、用户确认后清理本插件跟踪的输出，不自动清理网盘或媒体文件。账号、规则及历史版本保留。

## 当前验证范围

已依据官方公开 API 契约实现。本版未在 NAS 安装或进行账号、整理触发、播放、删除端到端实测；实际宿主是否返回完整整理目标路径仍需现场确认。

## 0.6.3 页面模块修复

前台和后台分别使用独立云盘识别模块，后台不再导入 ui 内文件；前端所有依赖仅位于 ui 内，避免共享后台依赖无法作为公开页面资源加载。修复前 NAS 的 ui/shared/clouds.js 返回404，页面入口及其他依赖正常。

## 0.6.3 界面

同步模式改为一行“定时同步 / 实时监控”，保留实际每分钟轮询说明，恢复增量与全量频率，定时与监控请求合并，全量优先。未接入网盘实时事件。

## 0.6.3 编辑弹窗排版

同步模式使用紧凑对齐的复选框与文字，修复全局 inline input 样式撑开复选框的问题。新增轻量分组、统一38px输入和目录按钮、缩短提示、优化后缀标签、滚动和固定操作区。同步逻辑与0.6.2相同。
